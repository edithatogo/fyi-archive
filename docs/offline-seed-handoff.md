# Offline seed handoff

The archive seed can import pre-acquired request, page and attachment evidence
through the explicitly selected `capture_offline_evidence` function. It copies the
saved response, result, receipt, WACZ and linkage into a private case directory,
checks them with the Rust verifier, and marks the case complete only after successful
validation. The attachment sidecar keeps the verified WARC record ID, content type
and size. The normal seed CLI continues to use its configured capture client.

The Offline seed handoff workflow builds the Rust CLI from the exact source commit
in `FYI_CLI_REVISION`. It runs the same binary for `verify-acquisition-receipt`
and `export-process-events` in a network-disabled namespace. The archive test checks
three receipt-linked WACZ captures and their exact response bytes, three timeline
events, the linked attachment, package checksums, and checkpoint restoration after
an event deletion. It also rejects corrupted evidence and an insufficient byte cap.

The fixture was generated by the in-process Rust source transport from fictional
case 701 on `source.invalid`. Its source fixture SHA-256 is
`83cff3bf9dc6e0930402a35e951475113f43446bf6be58bd791c01d7a3e14b62`.
The saved artifacts are checked in so the test starts from the same input on each run.

Build the pinned Rust revision and use the isolated Python 3.15.2 environment
to run the same test locally.

```sh
uv venv --python 3.15.2 .venv
uv pip sync --require-hashes --python .venv/bin/python .github/offline-seed-requirements.lock
FYI_OFFLINE_SEED_CLI=/absolute/path/to/rust/target/debug/fyi-cli \
  .venv/bin/python -m pytest -q tests/test_offline_seed_handoff.py
```

This fictional check covers the offline handoff. Release pin qualification and
production source-switch rollback remain part of archive cutover acceptance.
